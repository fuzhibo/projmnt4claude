# 调查报告：模板有效性验证测试

## 元数据
- **需求来源**: 测试需求：验证模板有效性
- **调查时间**: 2026-07-11
- **调查目录**: investigation-template-validation
- **语言**: zh

## 原因分析
### CA-001: 需要验证模板格式是否符合解析器契约
调查报告模板作为需求分析的核心输出产物，其格式必须与解析器严格匹配。当前需要验证以下格式约束是否被正确遵循：

- 标题层级结构（# → ## → ###）是否正确
- CA-NNN/SOL-NNN 编号格式是否符合解析器契约
- 检查点格式（[prefix] 描述 → SOL-NNN）是否完整
- Markdown 元素（代码块、表格、列表）是否规范

### CA-002: 需要确认模板字段填充完整性
模板中包含多个占位符字段，需要验证：

- 元数据字段（title、date、slug）是否被正确替换
- 原因分析与解决方案的编号是否一一对应
- 检查点是否覆盖所有解决方案要点

## 解决方案
### SOL-001: 建立模板格式验证机制 → 对应 CA-001
创建自动化验证脚本，检查模板输出是否符合解析器契约要求：

- 验证标题层级不跳级
- 验证编号格式为 CA-NNN/SOL-NNN（NNN 为 3 位数字）
- 验证检查点使用标准前缀：[ai review]、[ai qa]、[human qa]、[script]
- 验证检查点指向正确的解决方案编号
- 涉及文件: `src/utils/investigation/report-parser.ts`
- 预期变更: 新增模板格式校验函数

### SOL-002: 实现字段填充完整性检查 → 对应 CA-002
开发字段完整性验证逻辑，确保报告生成后无遗漏：

- 元数据字段完整性检查
- 原因-方案编号对应关系检查
- 检查点覆盖率检查
- 涉及文件: `src/utils/investigation/report-generator.ts`
- 预期变更: 增加输出后验证步骤

## 检查点覆盖清单

- [ai review] 验证模板格式校验逻辑是否符合解析器契约 → SOL-001
- [ai qa] 测试各种边界情况的模板格式检测 → SOL-001

### SOL-002 相关检查点

- [human qa] 人工确认报告输出格式符合预期 → SOL-002
